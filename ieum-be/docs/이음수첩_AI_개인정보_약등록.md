## 2.1 AI 모델과 개인정보 처리

### 원칙
개인정보는 AI로 보내기 전에 우리 서버 안에서 가린다. 사진은 AI로 보내지 않는다.

서버에서 OCR로 글자와 위치를 읽고, Presidio로 다음을 가린 뒤 가린 글만 AI로 보낸다.
- 주민번호 (고유식별정보)
- 이름
- 연락처
- 질병코드 (민감정보)

처리 순서는 **사진 → OCR → Presidio → LLM → 식약처 API**다.

### 사용 모델과 API

#### 말을 글로: OpenAI Whisper API (`whisper-1`)
- 한국어를 받아쓴다. 1회 3분까지.
- 음성은 가릴 수 없어서 원본이 미국으로 간다. 국외 이전 동의를 받는다.
- 받아쓴 글은 Presidio로 가린 뒤 Opus로 보낸다.

#### 사진 글자 읽기(OCR): korean-handwriting-rec + RapidOCR 3.x
- 모델: https://huggingface.co/Rebeccaaaaaaaa/korean-handwriting-rec
- PP-OCRv5 한국어 인식 모델(`korean_PP-OCRv5_mobile_rec`)을 AI Hub 손글씨·공문서 데이터로 추가 학습한 모델이다. 약 15MB ONNX, Apache-2.0.
- 우리 서버 CPU에서 돌고 외부로 보내지 않는다. 원본은 서버 안에만 둔다.
- 정확도(모델 카드 기준): 정부 서식 인쇄 글자 99.2%, 손글씨 단어 97.4%. "0.5알", "5mg" 같은 용량 표기에 유리하다.
- 이 모델은 글자 인식만 한다. 그래서 글자 영역을 찾는 검출 모델(RapidOCR 기본)을 함께 넣는다. 사진이 기울어질 수 있으면 방향 분류 모델도 넣는다.
- 첫 실행 때 모델을 내려받지 않도록 컨테이너 이미지에 미리 넣는다.
- 표와 줄 구조는 읽지 않는다. 그래서 글자 위치로 줄을 나눈 뒤 Opus에 넘긴다. 인식 신뢰도가 낮은 칸은 "확인 필요"로 표시한다.

#### 개인정보 마스킹: Presidio Analyzer, Anonymizer
- 저장소: https://github.com/data-privacy-stack/presidio (오픈소스, MIT)
- Analyzer가 개인정보를 찾고, Anonymizer가 가린다.
- 처리 대상: OCR 글, 사진, 직접 쓴 글, 받아쓴 글. 글에서는 가리고, 사진에는 OCR이 읽은 위치에 검은 상자를 칠해 저장한다.
- 기본 인식기는 영어 중심이라 한국어 인식기를 더한다.
  - 정규식: 주민번호, 휴대폰 번호, 이메일, 질병코드(KCD)
  - 이름 목록: 가입 때 입력한 보호자, 당사자, 임시 보호자 이름
- 정답 세트로 놓치는 비율을 잰다.
- OCR과 같은 Python 컨테이너에서 돌린다. Spring 서버가 REST로 부르므로 배포는 컨테이너 하나만 늘어난다.

#### 생성형 AI: Claude Opus 5.5 (`claude-opus-5-5`)
모든 AI 작업에 이 모델 하나만 쓴다. 모델 ID는 날짜를 붙이지 않고 그대로 쓴다. 100만 토큰당 입력 4달러, 출력 20달러.

하는 일
- **기록 정리, 원문 인용, 되묻기**: 정해진 JSON 서식으로 정리한다.
- **약 목록 정리와 쉬운 말**: 가린 OCR 줄을 약 이름, 용량, 복용 시간으로 묶고, 당사자용 쉬운 말로 바꾼다.
- **인수인계 이해 확인(8장)**: 답의 의미를 비교하고, 빠진 부분은 도구 호출로 다시 찾는다. 열린 단계 안의 정보만 쓴다.

호출 규칙
- 출력 형식은 structured outputs(`output_config.format`)로 JSON 서식을 고정한다.
- thinking은 끌 수 없으므로 effort로 속도를 맞춘다. 시작값은 정리 low, 에이전트 medium.
- 도구 강제 선택(`tool_choice`의 `any`, `tool`)은 받지 않으므로 `auto`와 strict 스키마를 쓴다.
- 거절에 대비해 서버 쪽 대체 모델(fallbacks)을 켠다.
- 비용: Haiku 5.5보다 입력과 출력 단가가 40배다. 그래서 팀 기획서의 가구당 월 비용(약 0.09달러)은 Opus 5.5 기준으로 다시 잰다.

#### 약 대조: 식품의약품안전처_의약품 제품 허가정보 (공공데이터포털 OpenAPI)
- 제품명(`item_name`), 보험코드(`edi_code`) 등으로 조회한다. 품목, 주성분, 허가번호, 전문/일반 구분 같은 허가 정보를 받는다.
- Opus가 정리한 약 이름은 허가 목록에서 가장 비슷한 이름으로 맞춘다.
- 주성분을 보고 주의 약 종류를 붙인다. 예: 와파린정은 "주의가 필요한 약, 혈액희석제".
- 시연은 미리 받은 약 목록(약 10종)으로 대조한다.

#### 원문 대조, 열람 판정: 규칙(서버 코드)
AI 없이 원문과 승인 기록을 대조한다.

## 3.2 약 등록

### 약 등록 흐름 (화면 A2, 그림 4)
1. **사진 찍기 (보호자)**: 약이 바뀐 날 복약안내문, 처방전, 약봉투 중 한 장을 찍는다. 약봉투는 받은 날 찍도록 안내한다.
2. **글자 읽기 (서버 OCR)**: korean-handwriting-rec이 글자와 위치를 읽는다.
3. **자동 가림 (규칙)**: Presidio가 주민번호, 이름, 연락처, 질병코드를 찾아 글과 사진을 가린다.
4. **가림 확인 (보호자)**: 자동으로 가린 사진을 보고, 빠진 곳만 손으로 더 가린다.
5. **약 목록 정리 (AI)**: Opus 5.5가 가린 글만 받아 약 이름, 용량, 복용 시간으로 묶는다.
6. **약 대조 (공공 API)**: 식약처 제품 허가정보와 대조하고 주의 약 종류를 붙인다.
7. **보호자 확정 (보호자)**: 흐린 용량은 "확인 필요"로 표시된다. 보호자가 고친 뒤 "맞아요, 저장"을 누른다.

### 화면과 보호 규칙
- 1단계에는 약 이름과 주의 약 종류가 함께 보인다. 와파린정은 1단계에 "혈액희석제 복용 중"으로도 보인다. 보호자는 약 이름을 숨길 수 있다(화면 L1c).
- 당사자 화면에는 약 이름이 나오지 않는다. "선생님과 약 먹기"처럼 쉬운 말로 바꿔 보여 준다.
- 용량은 보호자가 꼭 확인한다. OCR이 "0.5알"을 "5알"로 읽을 수 있기 때문이다. 그래서 인식 신뢰도가 낮은 용량은 "1정?"처럼 확인 필요로 표시한다.
- 사진은 해외로 보내지 않는다. 원본 사진과 가린 사진은 비공개 버킷에 둔다.
- 가린 글만 Anthropic(미국)으로 간다. 약 이름 같은 건강정보는 가린 글에도 남으므로 국외 이전 동의는 유지한다. 음성은 원본이 OpenAI(미국)로 간다.
- 건강정보 고속도로 연동은 확장 과제다. 복지부 지정 전문기관만 받을 수 있고(2025년 12월 첫 지정 3곳), 성인 자녀의 대리 조회도 아직 안 된다.
