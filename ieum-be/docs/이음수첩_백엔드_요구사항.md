# 이음수첩 · 백엔드 개발 요구사항

> 기준: 「이음수첩_결정사항.md」 (새 플로우 반영본, 2026-11-21)
> 범위: Java Spring 백엔드 + Postgres. 프론트(React TS)는 다루지 않습니다.
> 표기: **[확정]** 결정된 내용 / **[가정]** 답을 받지 못해 임시로 정한 것 / **[초안]** 구현을 위해 제안한 구조로 팀 합의가 필요함 / **[미정]**

---

## 0. 전제

| 항목 | 내용 |
| --- | --- |
| 런타임 | Java Spring, Railway 배포 **[확정]** |
| DB | Railway Postgres, 서버와 같은 싱가포르 리전 (Railway에 서울 리전 없음). 스키마는 Flyway `db/migration` **[변경: 서울 리전 → Railway]** |
| 프론트 연동 | Vercel(React TS)과 도메인이 달라 CORS 필수, HTTPS **[확정]** |
| 사용자 면 | 보호자 / 임시보호자·의료진 두 면. 보호대상자는 데이터로만 존재 **[확정]** |
| 운영자 기능 | 만들지 않음 **[확정]** |
| 외부 연락 | 실제 문자·112·119 연동 없음. 알림은 앱 안 알림과 모의 처리 **[확정]** |
| 가동 유지 | Railway 헬스체크(`/health`)로 배포를 확인한다. Railway DB는 멈추지 않으므로 주기 호출은 필요 없다 **[변경]** |

## 1. 역할과 권한

| 역할 | 인증 | 볼 수 있는 것 |
| --- | --- | --- |
| 보호자 (여러 명) | 회원가입 + 문자 인증(모의). 체험은 쿠키 세션 | 보호대상자의 모든 정보, 약·정보 등록, QR·코드 발급, 열람 기록, 상세조회 동의 |
| 의료진 (긴급조회) | 없음 **[가정]**. QR 토큰 또는 8자리 코드로 접근 | 보호자가 긴급조회용으로 고른 필수정보만 |
| 임시보호자·간병인 (상세조회) | 없음 **[가정]**. 보호자 동의 후 발급되는 열람 토큰 | 상세 정보 (기록 + 원문 인용, 약 정보). 주소 제외 **[가정]** |

## 2. 기능 요구사항

### FR-1 회원가입·로그인 (M1)

- FR-1.1 가입 항목은 **이름, 전화번호, 생년월일**이다 **[확정]**
- FR-1.2 문자 인증은 **모의**로 처리한다 (고정 코드, 실제 발송 없음) **[확정]**
- FR-1.3 전화번호는 계정마다 고유하다 **[초안]**
- FR-1.4 로그인은 전화번호 + 문자 인증(모의)으로 한다. 소셜 로그인은 만들지 않는다 **[확정]**
- FR-1.5 로그인 유지 방식(세션 쿠키 / JWT)은 **[미정]**
- FR-1.6 체험 모드는 쿠키 세션을 쓰고, 세션마다 `demo_sessions` 행을 만든다 **[확정]**

### FR-2 보호대상자 (M1)

- FR-2.1 보호자가 보호대상자를 등록한다. 보호대상자는 로그인하지 않는다 **[확정]**
- FR-2.2 등록 항목과 보호자 1명이 등록할 수 있는 보호대상자 수는 **[미정]** (가정: 1명)

### FR-3 보호자 연결 (M1)

- FR-3.1 핵심 보호자가 **초대코드**를 발급하고, 다른 보호자가 가입한 뒤 코드를 입력해 연결한다 **[확정]**
- FR-3.2 코드 형식·유효 기간·1회용 여부는 **[초안: 무작위 6~8자리, 24시간 만료, 1회용]**
- FR-3.3 초대를 수락하고 동의해야 성립한다. 수락 시각과 동의 시각을 저장한다 **[확정]**
- FR-3.4 한 보호대상자에 보호자를 **여러 명** 연결할 수 있다 **[확정]**
- FR-3.5 연결된 보호자 **목록 조회**: 이름, 역할(핵심/일반), 연결 시각 **[확정: 목록 / 초안: 항목]**
- FR-3.6 연결된 보호자는 누구든 상세조회에 동의할 수 있다 **[가정]**

### FR-4 동의 (M1)

- FR-4.1 항목별로 저장한다: 개인정보 / 건강정보 / 긴급조회 필수정보 공개 / 상세조회 제공 / 해외 AI 전송(Anthropic·OpenAI) **[확정]**
- FR-4.2 항목마다 동의 시각과 동의한 사람을 기록한다 **[확정]**
- FR-4.3 보호대상자 본인 동의 여부를 저장한다. 본인 동의가 없고 후견인도 없으면 민감 항목 공개를 서버에서 제한한다 **[확정]**
- FR-4.4 동의하지 않은 범위의 데이터는 어떤 응답에도 넣지 않는다. 프론트가 아니라 서버에서 강제한다 **[초안]**

### FR-5 정보 등록: AI 정리·인용 검증 (M4, M5)

- FR-5.1 입력은 글(최대 500자) 또는 음성이다. 음성은 Whisper로 바꾼 뒤 글과 같은 경로로 처리한다 **[확정]**
- FR-5.2 입력은 먼저 PII 필터(FR-11.1)를 거친다 **[확정]**
- FR-5.3 Claude가 항목별(알러지, 특이사항, 진정법, 루틴 등)로 정리하고, 항목마다 **원문 문장을 그대로 인용**한다 **[확정]**
- FR-5.4 **인용 검증 (규칙 기반, 외부 API 호출 없음)** **[확정]**
  1. 인용문이 원문에 있는지 찾는다 (공백·문장부호를 정규화한 뒤 부분 문자열로 비교) **[초안: 정규화 방식]**
  2. 정리문의 숫자가 인용문에 그대로 있는지 확인한다 ("0.5알", "반 알", 시각, 횟수)
  3. 부정어("없어요", "안 돼요", "먹지 않아요" 등)가 양쪽에 똑같이 있는지 확인한다
  4. 결과는 `pass` / `review` / `blocked`. 인용문이 원문에 없으면 `blocked` ("원문에 없는 말이라 저장을 막았어요")
  5. 숫자·부정어가 맞지 않을 때 `review`로 볼지 `blocked`로 볼지는 **[미정]**
- FR-5.5 체험 모드의 저장된 AI 응답에도 같은 검증을 실제로 실행한다 **[확정]**
- FR-5.6 "AI 실수 끼워 넣기": 원문에 없는 약을 넣은 응답을 검증기에 넣어 차단되는 것을 보여 준다 **[확정]**
- FR-5.7 보호자가 확인해야 저장된다. 확인 전에는 임시 상태로 둔다 **[확정]**
- FR-5.8 항목마다 `emergency_visible`(긴급조회 노출 여부)을 보호자가 정한다 **[확정]**
- FR-5.9 되묻기: 필수 항목 목록과 비교해 빠진 항목을 질문으로 돌려준다. 필수 항목 목록은 **[미정]**
- FR-5.10 항목마다 마지막 확인일을 두고, 30일이 지나면 `stale`로 표시한다 **[확정]**
- FR-5.11 평가셋 60건(시험 40건)을 검증기에 돌려 "40건 중 n건 차단, n건 놓침"을 산출한다 **[확정]**

### FR-6 약 등록 (M7)

경로 **[확정]**: 가린 사진 업로드 → OCR(Claude Opus) → 주민번호 형식 재삭제 → 약정보 API 확인 → LLM 쉬운 말 정리 + 인용 검증 → 보호자 수정·확정

- FR-6.1 서버는 **가린 사진만** 받고, 그 경로만 저장한다 **[확정]**
- FR-6.2 Opus 원응답(JSON)을 `medication_sources`에 저장한다 **[확정]**
- FR-6.3 OCR 결과에서 주민번호 형식을 다시 지운다 **[확정]**
- FR-6.4 약 이름은 심평원 표준코드(`drug_master`)로 확인하고 자동완성에 쓴다. 고위험 여부를 함께 둔다 **[확정]**
- FR-6.5 식약처 허가정보·e약은요 API로 약 정보를 확인한다 **[확정]**. 결과는 캐시한다 **[초안]**
- FR-6.6 정리문에도 인용 검증(FR-5.4)을 적용한다 **[확정]**
- FR-6.7 `medications`에 `quote_text`, `verify_status`, `ai_source`, `emergency_visible`을 둔다 **[확정]**
- FR-6.8 용량은 보호자가 확인하기 전에는 확정되지 않는다 **[확정]**
- FR-6.9 AI 출력에 판단·권고를 넣지 않는다 (약사법) **[확정]**
- FR-6.10 체험 모드는 샘플 처방전 하나와 저장된 응답을 쓴다. 24시간 대회라면 저장된 응답만 쓴다 **[확정]**

### FR-7 QR·8자리 연결코드 (M2)

- FR-7.1 로그인한 보호자만 발급할 수 있다 **[확정]**
- FR-7.2 QR에는 무작위 토큰만 넣고, 건강정보·이름·번호는 넣지 않는다 **[확정]**
- FR-7.3 8자리 연결코드는 QR과 같은 보호대상자를 가리키는 **고정 코드**다 **[가정]**. 형식은 **[초안: 숫자 8자리]**
- FR-7.4 다시 발급하면 이전 QR 토큰과 코드를 무효로 만든다 **[초안]**
- FR-7.5 코드 입력은 IP당 시도 횟수를 제한한다 (무작위 대입 방지) **[초안]**
- FR-7.6 실물 출력용 지갑 크기 PDF를 만든다. 서버에서 만들지 프론트에서 만들지는 **[미정]**

### FR-8 긴급조회 (M2)

- FR-8.1 QR 토큰 또는 8자리 코드로 들어와 "조회하기"를 누르면 필수정보를 반환한다. 인증·대기 없음 **[확정]**
- FR-8.2 반환 범위: `emergency_visible = true`이면서 긴급조회 공개에 동의한 항목만. 약은 종류만 보여 준다 **[확정]**
- FR-8.3 조회할 때마다 **기기정보(User-Agent)와 IP 해시**를 `access_logs`에 저장한다 **[확정]**
- FR-8.4 응답에 "조회 기록이 남습니다" 고지 플래그를 넣는다 **[확정]**
- FR-8.5 위치는 수집하지 않는다 **[확정]**
- FR-8.6 조회가 일어나면 연결된 보호자에게 앱 안 알림을 보낸다 **[가정]**

### FR-9 상세조회 (M3)

- FR-9.1 조회하는 쪽이 상세조회를 요청하면 `detail_requests`를 만들고, 마감 시각을 지금으로부터 **10분 뒤**로 둔다 **[확정]**
- FR-9.2 요청자 정보: 기기정보와 IP 해시를 저장한다. 요청자 번호는 선택이며, 받으면 30일 뒤 파기한다 **[확정: 번호 null 허용·30일 파기 / 가정: 선택 입력]**
- FR-9.3 연결된 보호자 전원에게 알린다 (앱 안 알림, 모의) **[확정]**
- FR-9.4 보호자는 동의하거나 거절할 수 있다. 마감 뒤의 동의는 거부한다. 10분 판정은 서버 시각으로 한다 **[확정: 10분 / 초안: 거절]**
- FR-9.5 동의하면 기간 있는 **열람 토큰**을 발급한다. 열람 기간은 **[미정]**
- FR-9.6 요청자 쪽 상태 조회는 **2초 폴링**을 감당해야 한다. 동의되면 "보호자가 확인했어요" 상태와 열람 토큰을 돌려준다 **[확정]**
- FR-9.7 10분 안에 동의가 없으면 `expired`로 바꾼다. 요청자는 긴급조회 정보만 볼 수 있고 다시 요청할 수 있다 **[가정]**
- FR-9.8 상세 정보 응답 **[확정]**
  - 확정된 기록 + 원문 인용
  - 약: 이름을 가린 사진, 고위험 약 여부, 약국 전화, "출처: 식품의약품안전처"
  - 고정 문구 "보호자가 적은 돌봄 방법이며 의료 지시가 아닙니다. 마지막 확인: 날짜"
  - 주소는 넣지 않는다 **[가정]**
- FR-9.9 상세 정보를 열람할 때마다 `access_logs`에 기록한다 **[초안]**

### FR-10 보호자 쪽 조회 (M2, M3, M5)

- FR-10.1 열람 기록 목록: 종류(긴급/상세요청/상세열람), 시각, 기기정보 **[확정]**
- FR-10.2 대기 중인 상세조회 요청 목록과 남은 시간 **[초안]**
- FR-10.3 홈: 기록 버튼, 꼭 남길 정보(되묻기), 30일 지난 항목 **[확정]**

### FR-11 공통 입력 처리·호출 제한

- FR-11.1 PII 필터: 주민번호·전화번호·이메일 형식을 서버에서 지운 뒤 AI로 보낸다 **[확정]**
- FR-11.2 입력 원문은 어떤 로그에도 남기지 않는다 **[확정]**
- FR-11.3 직접 입력 제한: 세션당 5회, IP당 하루 20회, 전체 하루 300회, 500자 **[확정]**
- FR-11.4 AI 호출은 `ai_calls`에 기록한다 (원문 제외) **[확정]**
- FR-11.5 Anthropic 월 지출 한도를 둔다 **[확정]**. 한도·제한에 걸리면 저장된 응답으로 대체한다 **[초안]**

### FR-12 보관·삭제

- FR-12.1 체험 데이터는 24시간 뒤 삭제한다 **[확정]**
- FR-12.2 요청자 번호는 30일 뒤 파기한다 **[확정]**
- FR-12.3 정리 함수 `ieum_cleanup()`이 FR-12.1·12.2를 처리한다. pg_cron이 있으면 10분마다 예약되지만 Railway Postgres에는 없어서, 데모에서는 자동으로 돌리지 않는다. 필요하면 직접 실행한다 **[변경]**

### FR-13 체험 모드 (M8)

- FR-13.1 세션을 시작하면 가상 가구(보호자 박지은, 어머니)를 복제한다 **[확정]**
- FR-13.2 현재 단계를 서버에 저장하고, 노트북과 폰이 같은 세션을 공유한다 (2초 폴링) **[확정]**
- FR-13.3 화면 속 QR을 폰으로 찍으면 같은 세션의 조회 화면으로 이어진다 **[확정]**
- FR-13.4 단계 **[가정]**: ① 정보 등록·AI 실수 차단 → ② 의료진 긴급조회 → ③ 간병인 상세조회 요청·보호자 동의 → ④ 상세 정보 열람
- FR-13.5 "샘플 음성 변환해 보기": 서버에 있는 샘플 음성을 Whisper로 변환한다 **[확정]**
- FR-13.6 끝 화면에 "40건 중 n건 차단" 수치를 제공한다 **[확정]**

## 3. DB 설계 **[초안]**

기존 `db/schema.sql`과 대조해 합치세요. id는 모두 `gen_random_uuid()` **[확정]**.

| 테이블 | 주요 칼럼 |
| --- | --- |
| `guardians` | id, name, phone(고유), birth_date, demo_session_id, created_at |
| `care_recipients` | id, name, birth_date 등 **[미정]**, self_consent, guardian_of_record |
| `recipient_guardians` | recipient_id, guardian_id, role(primary/member), joined_at, consent_at |
| `guardian_invites` | id, recipient_id, code, issued_by, expires_at, used_at, used_by |
| `consents` | recipient_id, item, agreed, agreed_at, agreed_by |

## 6. 비기능 요구사항

- 보안: HTTPS, CORS는 Vercel 도메인만 허용 **[초안: 허용 범위]**
- 토큰·코드: 무작위 값으로 만들고, 8자리 코드는 시도 횟수를 제한한다 **[초안]**
- 개인정보: PII 필터, 원문 로깅 금지, IP 해시, 위치 미수집, 가린 사진만 저장 **[확정]**
- 안정성: AI 호출이 실패하면 저장된 응답으로 대체해 체험이 끊기지 않게 한다 **[초안]**
- 성능: 상태 조회와 알림은 2초 폴링을 감당해야 한다 **[확정]**

## 7. 작업 순서

1. **M1**: 뼈대, 배포·CORS, 헬스체크, 가입·로그인, 보호대상자, 동의, 보호자 연결
2. **M8**: 체험 세션, 가상 가구, 단계 동기화, 저장된 응답, 호출 제한
3. **M2**: QR·코드, 긴급조회, 열람 기록, 알림
4. **M3**: 상세조회 요청·10분 동의·열람 토큰
5. **M4**: AI 정리, 인용 검증, 평가셋 (승기님)
6. **M5**: 되묻기, 홈
7. **M7**: 약 등록, Whisper
